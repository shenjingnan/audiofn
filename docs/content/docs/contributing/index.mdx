# 参与贡献

欢迎为 AudioFn 贡献代码！本篇面向想参与开发的同学，介绍从零搭建开发环境到提交 PR 的完整流程；如果你只是想**使用** AudioFn，请看[介绍](/docs)。

> 完整的 CLI 参数、配置段与 audio.cpp 引擎说明见仓库 [CONTRIBUTING.md](https://github.com/shenjingnan/audiofn/blob/main/CONTRIBUTING.md)。

## 开发环境

| 工具 | 版本 | 用途 |
| ---- | ---- | ---- |
| Rust | 1.97.1（由 `rust-toolchain.toml` 固定） | 编译 / 测试 / Lint / Format |
| pnpm | 10.x（`packageManager` 固定） | Tauri CLI / 桌面前端 / 文档站依赖管理 |
| Node | 见 `.node-version` | 文档站与前端工具链 |
| Linux 额外依赖 | `libasound2-dev`（CLI 音频）、`libwebkit2gtk-4.1-dev` 等（Tauri） | 构建桌面应用需要 |

桌面应用开发前还需放置 audio.cpp 引擎 sidecar：

```bash
scripts/fetch-audiocpp-dev.sh          # 从 Release 下载；--build 走源码编译
```

## 常用命令

### CLI

```bash
cargo run                           # 直接运行（无参进入帮助）
cargo run -- asr install-model      # 下载 ASR 模型
cargo run -- asr transcribe --wav rec.wav
cargo run -- tts install-model      # 下载 TTS 模型
cargo run -- tts voices
cargo run -- completion bash        # 生成 shell 补全
```

### 桌面应用（Tauri 2，位于 `src-tauri/`）

```bash
pnpm install                        # 首次：安装 @tauri-apps/cli
pnpm tauri dev                      # 开发模式（热重载）
pnpm tauri build                    # 构建当前平台安装包（macOS: .app/.dmg）
cargo check -p audiofn-app          # 仅检查 tauri crate（Linux 需 webkit 依赖）
cargo clippy -p audiofn-app -- -D warnings
```

### 文档站（`docs/`）

```bash
pnpm --filter audiofn-docs test     # 平台检测逻辑单测
pnpm --dir docs build               # 静态导出（CI 校验同款）
```

## 测试与代码质量

```bash
cargo test                          # 运行测试
cargo test -- --test-threads=1      # 单线程测试（避免 env 竞争）
cargo fmt --check                   # 格式检查
cargo clippy -- -D warnings         # 严格 Lint
typos .                             # 拼写检查（typos-cli）
cargo fmt --check && cargo clippy -- -D warnings && cargo test   # 完整检查（CI 同款）
cargo tarpaulin                     # 覆盖率报告
pnpm --dir src-tauri/frontend test:run   # 桌面前端单测（vitest）
pnpm --dir src-tauri/frontend check      # 桌面前端 Lint（biome）
```

模型相关测试需要先安装模型（`cargo run -- asr install-model` 等）。

## Git 工作流

### 分支命名

- `feature/xxx` — 新功能
- `fix/xxx` — Bug 修复
- `docs/xxx` — 文档更新
- `refactor/xxx` — 重构

### Commit 规范

遵循 [Conventional Commits](https://www.conventionalcommits.org/)：

```
<type>(<scope>): <description>

[optional body]
```

| 类型 | 说明 |
| ---- | ---- |
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `docs` | 文档更新 |
| `style` | 代码格式 |
| `refactor` | 代码重构 |
| `perf` | 性能优化 |
| `test` | 测试相关 |
| `chore` | 构建 / 工具 |

## 提交 PR

1. 从 `main` 切出符合命名规范的分支。
2. 开发并确保本地通过完整检查：`cargo fmt --check && cargo clippy -- -D warnings && cargo test`（涉及桌面应用时另跑 `cargo clippy -p audiofn-app -- -D warnings` 与前端 `check` / `test:run`）。
3. 按规范提交 commit，推送并向 `main` 发起 PR，描述清楚动机与改动点。
4. CI 通过、Review 通过后合并；版本发布由 release-plz 自动完成，无需手动 bump。
